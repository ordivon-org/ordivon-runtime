## Durable results to carry forward

Do not restart RF0 from the existing `Job / Attempt / Process` object model.

Carry these results:

1. `Process` is a realization substrate/view, not the foundation root.
2. `State transition` is a general behavior-modeling grammar, not a sufficient Runtime definition.
3. Broad runtime ancestry is provisionally `selected/specifiable behavior → realization → lifecycle/observation`.
4. Ordivon Runtime is a strengthened branch for durable Agent-selected operational realization under interruption/effect ambiguity.
5. Preserve three planes:

```text
intentional/specification
ontic/realization
epistemic/evidence
```

and keep semantic/normative completion above Runtime unless a later round proves otherwise.
6. `Recovery != Retry`; retry requires effect semantics.
7. `Process exit != global termination != external finality != semantic completion`.
8. `Observation != Reality`; passive projection and reconciliation may have different causal semantics.
9. `Effect` is relative to a declared world/projection boundary.
10. `Workspace`, finite Job execution and the existing Effect Kernel are current specializations, not yet foundation primitives.

## Provisional hypothesis to attack

Broad Runtime candidate:

> A runtime is a realization boundary that takes a selected executable specification or operation under some authority/environment, participates in producing a concrete behavior in Reality, and exposes enough lifecycle/control/observation structure for another participant to relate that behavior back to the selection.

Ordivon-specific candidate:

> Ordivon Runtime is a durable, authority-bounded realization-and-convergence layer for Agent-selected local operations.

Neither is frozen.

## RF1 exact frontier

Enter:

# RF1 — State, Change, Event, Transition, Behavior and Dynamics

Core questions:

```text
What is a state?
Is state intrinsic or projection-relative?
What is change if state representations differ?
What distinguishes event from transition?
What makes a transition atomic versus composite?
What is behavior/trajectory in concurrent and continuous systems?
What is causation versus correlation/order?
What does it mean for a Runtime to realize a transition?
When is a system reactive, autonomous, controlled, or merely evolving?
How do discrete and continuous dynamics relate?
Can an action be defined before agency/intent is solved?
```

Mandatory falsifiers:

```text
pure deterministic computation
nondeterministic program
concurrent shared-memory object
distributed message system
long-running reactive service
database transaction
filesystem mutation
network side effect
robot/physical actuator
financial order
human delegated action
continuous physical process
observation-only system
```

Do not enter RF2 action/intent semantics until RF1 has separated `state`, `event`, `transition`, `behavior` and `dynamics` well enough that `action` does not silently inherit all of them.
