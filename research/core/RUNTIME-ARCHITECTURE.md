# Runtime Architecture

## Owner contract

Ordivon Runtime owns the bounded operational layer in which an admitted operational commitment is carried through concrete realization under explicit authority, resource, dependency and execution constraints, with effects, evidence and reconciliation scoped to the contracts Runtime actually controls.

A useful owner-native compression is:

```text
Proposal / request
  -> admission
  -> identity-bearing Operation / operational commitment
  -> concrete binding and realization policy
  -> Attempt / realization episode(s)
  -> effects / observations / records / evidence
  -> reconciliation / continuation / lifecycle standing
```

This is deliberately narrower than a universal theory of execution and deliberately broader than the current production object model.

## Six Foundation Families

1. **Operational Commitment & Realization**
2. **Boundary / Authority / Resource / Isolation**
3. **Behavior / Interaction / Composition**
4. **Failure / Effect / Persistence / Reconciliation**
5. **Evidence / Claim / Truth Scope**
6. **Lifecycle / Retention / Standing**

See [`FOUNDATION-FAMILIES.md`](FOUNDATION-FAMILIES.md) for provenance.

## What Runtime does not own

- Abstract semantics of computational descriptions, semantic comparison/refinement, or semantics-preserving composition/transport as such: **SCD** owns these.
- Reality ontology, external causal truth, measurement truth, or real-world entity identity: **World / Reality** and source/domain owners own these.
- Generic purposive Task continuity or Goal success: **Host / relevant semantic owners** own these.
- Agent cognition, working-set construction, reasoning, tool selection, or cognitive-loop semantics: **Harness / Agent** owns these.
- Generic network/inter-locus communicability, topology, forwarding or transport ontology: **Network** owns these.

## SBF reconciliation

SBF0–SBF23 remain immutable research identities and provenance. Their current presentation is role-sensitive:

- abstract computational-description semantics -> SCD;
- concrete admitted-Operation binding / deferred resolution / shared realization / reuse-discharge / invalidation-revalidation / support-evidence / lifecycle projections -> Runtime;
- reality grounding, causal external validity, observation/reference and source reliability -> World and source/domain epistemic bridges;
- superseded owner assignments remain historical validation, not current dual authority.

SBF2 abstract compatibility/equivalence/refinement is currently a Runtime<->SCD bridge with abstract ownership in SCD / SCDF3.

SBF3 abstract refinement composition/transport is currently a Runtime<->SCD bridge with abstract ownership in SCD / SCDF2 + SCDF5.

See [`SBF-OWNER-ROLE-MAP.md`](SBF-OWNER-ROLE-MAP.md) for claim-by-claim disposition.
