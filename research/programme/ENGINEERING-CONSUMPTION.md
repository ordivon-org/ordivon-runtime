# Programme Engineering Consumption

The programme exists to make Runtime research useful without forcing theory directly into production schemas.

## Consumption record

Each consumption item should contain:

```text
Consumer / problem
Observed failure or ambiguity
Relevant Runtime law(s)
Required distinctions
Minimal engineering consequence
Falsifier / regression test
Observed outcome
Theory disposition: confirmed | narrowed | falsified | unresolved
```

## Priority consumption themes

1. **Identity conservation** — request / Operation / Attempt / realization / effect separation in retry, recovery and provider interaction.
2. **Scope conservation** — prevent local execution evidence from becoming stronger global/semantic success claims.
3. **Open-world re-grounding** — reconcile external effects and current authority before consequential repetition after ambiguity.
4. **Standing/currentness** — distinguish retained history from current operational authority and validity.
5. **Fresh-execution non-necessity** — reuse validated standing support and compute only an unsatisfied support gap when contracts permit.
