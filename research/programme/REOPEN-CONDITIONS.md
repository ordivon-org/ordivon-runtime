# Runtime Theory Reopen Conditions

Foundation-level Runtime research is closed by default. `WholeRuntimeExhaustiveClosure = UNKNOWN` does not itself constitute a reason to reopen.

## Admissible reopen triggers

### R1 — Identity insufficiency

A real case cannot be represented without collapsing semantically distinct identities or inventing an ad hoc identity class outside the current theory.

### R2 — Scope/support contradiction

A required operational claim cannot be stated without violating current Scope Conservation, or current theory forbids a claim for which a sound support argument exists.

### R3 — Standing/currentness failure

A real recovery/currentness case cannot determine which retained claim remains current without semantics absent from the current lifecycle/standing family.

### R4 — Realization-class novelty

A materially new realization topology or support/discharge pattern defeats the current commitment/binding/realization model.

### R5 — Composition/order failure

A real system requires a composition or order relationship that current Non-Upgrading Composition or Typed Order Grammar cannot represent correctly.

### R6 — Open-world recovery failure

Reconciliation/re-grounding cannot construct an admissible continuation in a real case although sufficient authoritative evidence exists.

### R7 — Owner-boundary contradiction

Runtime and another semantic owner both appear to own the same mutable truth, or neither can legitimately own a necessary operational claim.

### R8 — Cross-domain repeated anomaly

The same unexplained failure class appears independently across multiple dogfood domains, indicating a missing theory rather than a local engineering defect.

## Non-triggers

The following do not justify reopening by themselves:

- a new paper, framework or analogy;
- desire for a more elegant taxonomy;
- unused Foundation numbers;
- `WholeRuntimeExhaustiveClosure = UNKNOWN`;
- a production feature request that current theory already explains;
- a single local bug with a clear engineering fix.

## Reopen decision output

Any reopen proposal must state:

```text
Concrete falsifier
Current law/family challenged
Why engineering-only repair is insufficient
Minimum theoretical question
Affected owner boundaries
Expected falsification result
```
